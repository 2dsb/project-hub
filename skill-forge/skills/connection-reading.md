# 连接导向阅读辅助

**触发条件**：用户输入一段文本并说"帮我分析""连接阅读""识别约束""阅读辅助"，或在讨论阅读材料时说"这段讲了什么"。

**核心原则**：阅读的本质不是收集概念，是收集约束——有了足够的约束，概念网络才会从模糊变为精确。约束在三个层面同时存在：(1) 词句层——概念之间的约束关系（定义、因果、对立等）；(2) 句段层——句子如何串联成连贯的段落论证；(3) 段篇层——段落如何组合成文章的整体架构。AI 的角色是三层约束关系的识别加速器，帮助用户构建多层概念约束图而非逐句摘要。

**配对 skill**：
- [探究式作文辅助](inquiry-essay.md) — 同一个概念约束图，阅读 skill 帮你提取三层约束（解网），写作 skill 帮你构建三层约束（织网）。
- [结构深潜验证](structural-deep-dive.md) — connection-reading 产出初始三层标注（广度），本 skill 通过自然语言叙述+提问纠错进行逐段验证与框架修正（深度）。

## 离线

**用户职责**：

1. **准备阅读材料**：将需要分析的文本准备好（可直接粘贴，也可告知 AI 文件路径）。
2. **标记不确定的约束**：AI 标注约束关系后，用户在自己不确定的标注旁标记"？"，后续可追溯原文验证。不确定项包括概念约束（词句层）和结构关系（句间/段间层）——任何一层的 AI 标注都可以质疑。
3. **手动构建多层概念约束图**：阅读完成后，不看原文尝试画出三层图——先画段间结构（哪些段是什么关系），再画段内句间结构，最后填充概念约束关系。画不出来的就是没真正理解的。
4. **检验图的质量**：检查四类指标——
  - 概念约束图：是否有孤立概念？是否有矛盾边？边密度是否支撑文章的论证力度？
  - 结构图：覆盖率是否足够（多数句子/段落都参与了结构边）？连通性是否良好（有没有孤立的句子/段落）？层次深度是否一致？有没有冗余边（同一对单元上有多个同类型边）？
5. **跨文章比较**：两篇同主题文章，概念标签不同但约束结构相同 → 在说同一件事。概念相同但约束结构不同 → 在同一领域内有实质性分歧。
6. **训练模式的使用**：当用户想培养自身的多层约束识别能力时，使用训练模式——AI 按宏观→微观顺序（段间→句间→词句层）提示，用户自己判断，AI 再给出答案。不要跳过"自己判断"这一步。如果在某层表现优秀（>90% 正确率），可以提议跳过该层的后续训练段落，但用户决定是否跳过。

## 一、共享数据层：三文件结构

> **约束关系类型库**：[shared/constraint-types.md](shared/constraint-types.md) — 概念间约束关系（24 种类型）— 词句层面
> **文本结构类型库**：[shared/text-structure-types.md](shared/text-structure-types.md) — topic→elaboration 为唯一结构关系 + 语义角色对 + 兄弟关系 — 句→段→篇层面
> **结构-约束映射层**：[shared/structure-constraint-mapping.md](shared/structure-constraint-mapping.md) — 双向映射，连接两个类型库，辅助 AI 推理
>
> 阅读是解网（提取约束+结构），写作是织网（编码约束+结构）——三文件在两个方向共用。

## 补充规则

- 文本过长（>2000 字）时，A 模式分段处理，每段标注后询问"继续下一段？"
- 用户说"这段我不确定"→ AI 重新逐句分析该段，不跳过任何句子
- 英文文本 → 约束类型和结构类型名称保持中文，但例句可包含英文
- 约束类型库和结构类型库是共享的——新类型同时适用于 inquiry-essay
- Mermaid 图 >8 段时 → 使用段组折叠表示（见 mermaid-subgraph-spec.md 第四节），提示用户可以展开单段查看句层
- Mode B 用户选择"不需要"深潜 → 尊重选择，当前 session 不再次提示（除非用户主动说"再看看段落结构"或"分析一下文章结构"）
- Mode C 用户在某层表现优秀（>90% 正确率）→ AI 提议可跳过该层的后续训练段落，但不自动跳过
- 自动提取机制（Sub-step 2D）在每个 session 结束时触发一次——不在 session 中间打断用户
- **约束类型库回补**：Sub-step 2D 触发后，将新出现的约束类型按以下流程补充到 shared/ 文件：(1) 列出所有新出现的约束标签，与 constraint-types.md 和 text-structure-types.md 逐一对比；(2) 出现 ≥3 次的纳入类型库，1-2 次但含义清晰的标注为"初步"，仅 1 次的归入已有类型；(3) 按扩展机制（暂停→命名→定义→追加）写入对应文件；(4) 更新 structure-constraint-mapping.md 中的相关映射；(5) 告知用户本次新增/归并/暂不纳入的情况。用户说"整理新出现的约束"时也可独立触发此流程。
- 无约束/无结构的文本（纯叙事、描述性文本）→ 标注为"约束密度低 / 结构松散"，切换到叙事分析模式而非强制套用论证框架
- 从 connection-reading 切换到 inquiry-essay 时 → 已提取的概念约束图和结构图可直接作为写作输入；如果用户已有阅读分析结果，主动询问"是否要基于已有分析图开始写作？"
- Mermaid 输出中，概念约束边用 constraint-types.md 的中文名称标注；句间/段间结构边用 text-structure-types.md 的英文简写标注（如 `thesis→support`），保证图的紧凑可读
