# 结构深潜验证

**触发条件**：用户已有 AI 标注了句间结构与概念约束的文本（通常由 [connection-reading.md](connection-reading.md) 或 [bilingual-reading.md](bilingual-reading.md) 产出），说"深潜这一段""验证标注""用自然语言叙述""这个标注对吗"。

**核心原则**：AI 的初始三层标注（词句层约束 + 句间结构 + 段间结构）不可避免地包含错误和遗漏——因为标注是逐条进行的，但论证是整体运行的。自然语言叙述强迫所有标注在同一段话里**互相印证**：如果在叙述中两个标注之间的逻辑断裂、或某句被回避、或逻辑推进不连贯，那就是标注本身有问题。表和标签不会暴露这种不连贯，自然语言会。

**配对 skill**：[connection-reading.md](connection-reading.md) — 产出初始三层标注；本 skill 对其进行深度验证与修正。两者的关系是：connection-reading 做广度（全量标注），structural-deep-dive 做深度（逐段验证）。

---

## 离线

**用户职责**：

1. **准备已标注文本**：确保目标段落已经过 AI 的初始三层标注（来自 connection-reading Mode A/B，或 bilingual-reading Step 3-4）。
2. **逐段深潜**：不要一次性深潜全章——每轮聚焦一段（通常 4-6 句），完成三步流程后再进入下一段。
3. **质疑一切**：自然语言叙述中任何一个让你觉得"这里不对""这句话被跳过了""这个关系说不通"的地方，都是潜在的标注错误。不要因为是 AI 说的就跳过。
4. **用自己的语言重述**：三步流程的最后一步是用户自己的自然语言重述——不是复述 AI 的叙述，而是在理解之后用自己的话重新表达。这是检验是否真正理解的唯一标准。
5. **触发共享文件更新**：深潜过程中发现的框架性问题（如新约束类型、结构类型辨析不清、光谱位置错误），必须同步更新到 `skills/shared/` 下的对应文件。

## 补充规则

- 每次深潜聚焦一段（通常 4-8 句），完成三步流程后再进入下一段。深潜不是标注——标注可以批量，深潜必须逐段
- 提问与纠错循环（第二步）AI 不主动结束——由用户决定何时理解到位
- 任何对共享文件的修正必须同步更新该文件的演进记录
- 深潜发现的新约束类型或结构类型，同样触发 constraint-types.md 和 text-structure-types.md 的扩展机制
- 如果某段的初始标注来自 connection-reading Mode B（用户回忆驱动），深潜前需要先对 AI 建议的虚线标注进行确认或拒绝
- 用户说"这个我知道，不用深潜"→ 跳过该段，尊重用户判断
- 自然语言叙述中如果发现跨段意象复现（如同一概念组在不同段中的功能演变），标注但不强制纳入结构类型——目前框架不覆盖意象层面的分析
- 本 skill 与 inquiry-essay.md 的关系：深潜中形成的结构和约束理解，可以在写作时作为概念约束图的参考
