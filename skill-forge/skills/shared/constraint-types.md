# 约束关系类型库

> 共享于 [connection-reading.md](../connection-reading.md)、[inquiry-essay.md](../inquiry-essay.md) 和 [bilingual-reading.md](../bilingual-reading.md)。阅读是解网（提取约束），写作是织网（编码约束）——同一个类型库，两个方向。

## 一、概念约束关系类型

概念约束关系描述**概念与概念之间**的逻辑关系。每次标注回答：这一句对概念 A 和概念 B 之间的关系**新增了什么约束**？

### 基础逻辑关系（9 种）

| # | 约束关系 | 含义 | 例句模式 | 识别信号词 |
|---|---------|------|---------|-----------|
| 1 | **A 定义 B** | A 精确界定了 B 的内涵 | "X 指的是……" / "X 的定义是……" | 指的是、定义为、即、所谓 |
| 2 | **A 详细化 B** | A 是 B 的具体展开/细化 | "具体来说……" / "包括以下几个方面……" | 具体来说、包括、分为、例如 |
| 3 | **A 是 B 的结果** | B 导致了 A（因果） | "因此……" / "由此产生了……" | 因此、所以、导致、由此 |
| 4 | **A 是 B 的起源** | A 是 B 的来源/起点 | "起源于……" / "在……基础上发展而来" | 起源于、来自、基于、源于 |
| 5 | **A 的价值在于 B** | B 是 A 的价值/意义锚点 | "X 的意义在于……" / "X 之所以重要，是因为……" | 意义在于、重要的是、之所以 |
| 6 | **A 是 B 的反例** | A 否定了 B 的普遍性 | "然而……" / "并非如此……" | 然而、但是、并非、恰恰相反 |
| 7 | **A 以 B 为前提** | B 是 A 成立的必要条件 | "只有在……情况下" / "前提是……" | 前提是、只有……才、取决于 |
| 8 | **A 与 B 互斥** | A 和 B 不能同时成立 | "要么……要么……" / "与……矛盾" | 要么……要么、矛盾、不能同时 |
| 9 | **A 的程度取决于 B** | B 调节 A 的强度/大小 | "越……越……" / "随……而变化" | 越……越、随着、取决于……程度 |

### 比较与张力关系（4 种）

| # | 约束关系 | 含义 | 例句模式 | 识别信号词 |
|---|---------|------|---------|-----------|
| 10 | **A 权衡 B** | A 和 B 不可同时最大化，改善一方必然削弱另一方 | "X 和 Y 之间存在取舍" / "追求 X 意味着牺牲 Y" | 权衡、取舍、代价是、不能同时 |
| 11 | **A 对比 B** | A 和 B 在指定维度上存在差异（不等于互斥） | "X 与 Y 的不同之处在于……" / "相比之下……" | 相比之下、不同的是、与……相比、前者……后者 |
| 12 | **A 反直觉于 B** | A 与关于 B 的常识/直觉相反 | "令人惊讶的是……" / "直觉上 X 应该……但实际上……" | 令人惊讶、反直觉、表面上……实际上、竟然 |
| 13 | **A 是同构于 B** | A 和 B 在约束结构上相同，但发生在不同领域 | "X 本质上是同样的逻辑" / "这与 Y 如出一辙" | 同理、如出一辙、同样的逻辑、与……同构 |

### 证据与方法关系（5 种）

| # | 约束关系 | 含义 | 例句模式 | 识别信号词 |
|---|---------|------|---------|-----------|
| 14 | **A 证据支持 B** | A 为 B 提供实证/数据支撑 | "数据显示……" / "例如……"（当例子是证据时） | 数据显示、研究表明、实验表明、据统计 |
| 15 | **A 预测 B** | 从 A（理论/模型）推导出可检验的 B | "理论预测……" / "如果 X 成立，我们应观察到 Y" | 预测、预期、如果……应该、可以推断 |
| 16 | **A 反事实于 B** | 假设条件不同于 B 时，A 描述了会发生什么 | "如果……（与事实相反的条件），那么……" | 如果（与事实相反）、假设、假如 |
| 17 | **A 机制实现 B** | A 描述了 B 通过什么具体机制/过程运作 | "X 通过以下方式实现 Y……" / "其运作机制是……" | 通过、机制是、运作方式、其原理是 |
| 18 | **A 结构组成 B** | A 描述了 B 的内部结构/组成/配置 | "X 由以下部分构成……" / "其结构包括……" | 由……构成、包括……部分、其结构、组成 |

### 目的与行动关系（6 种）

| # | 约束关系 | 含义 | 例句模式 | 识别信号词 |
|---|---------|------|---------|-----------|
| 19 | **A 目的是 B** | B 是 A 的目的/意图 | "X 的目的是……" / "旨在……" | 目的是、旨在、为了、意在 |
| 20 | **A 解决 B** | A 是 B（问题）的解决方案 | "解决 X 的方法是……" / "应对措施是……" | 解决方案、应对、方法是、为此 |
| 21 | **A 策略达成 B** | A 是为实现 B 而采取的策略/手段 | "X 的策略是……" / "通过……来……" | 策略、手段、通过……来、方式是 |
| 22 | **A 是 B 的例外** | A 是 B（规律/模式）的例外情况 | "例外的是……" / "X 不适用于 Y 的情况" | 例外、除非、除了、不适用于 |
| 23 | **A 原则指导 B** | A 是一般原则/规律，B 是其适用范围或表现 | "一般规律是……" / "X 的原则是……" | 原则、规律、一般情况、通常 |
| 24 | **A 模式复现 B** | A 是模式 B 的又一次出现/实例 | "这再次印证了……" / "同样的模式出现在……" | 再次、重现、同样的模式、反复出现 |

## 二、元标注类型

元标注不描述概念间的关系，而是标注**分析过程本身**的状态。用于辅助阅读节奏和后续追溯。

| 标签 | 含义 | 使用场景 |
|------|------|---------|
| `[无约束]` | 该句不新增概念约束关系 | 修辞句、纯举例（无分析）、重复前文 |
| `[精炼]` | 该句提炼了前面多句的核心逻辑洞见 | 关键 insight 句，值得反复读 |
| `[核心]` | 该句是章节/段落的中心论点 | 全文/全章的枢纽句 |
| `[参考]` | 该句引用外部来源/文献 | 标注出处，便于追溯 |
| `[评估]` | 该句对某事物做出价值判断/评估 | 作者的主观评价或政策判断 |
| `[未解决]` | 该句承认问题尚未解决/存在困境 | 开放问题，作者不做结论 |

## 三、扩展机制

当遇到无法归入已知 24 类的约束关系时：
1. **暂停**：确认这确实是一个新的约束类型，而非已有类型的变体
2. **命名**：用"A [关系] B"的格式命名，判断属于"基础逻辑/比较张力/证据方法/目的行动"中的哪个大类
3. **定义**：写出含义、典型例句模式和识别信号词
4. **追加**：将新类型加入本文件对应大类，重新编号

类型库是**活的**——随着阅读和写作量的增加而生长。任何一方（connection-reading 阅读方向、inquiry-essay 写作方向、bilingual-reading 双语书分析）发现的新类型，自动适用于所有使用本类型库的 skill。

## 四、约束的结构性光谱

24 种概念约束在论证中不是平等的。它们有一个隐性光谱，从"纯概念——暴露后沉入背景，被使用但不被展开"到"概念+结构枢纽——暴露后组织后续论证"。

### 三个区域

| 区域 | 特征 | 暴露后的行为 | 典型约束 |
|------|------|------------|---------|
| **纯概念** | 暴露一次后完成。后续论证将其作为已知条件使用，不对它本身进行 elaboration。 | 沉入背景 → 不再被直接讨论 | `[权衡]` `[前提]` `[反直觉于]` `[例外]` |
| **中间态** | 可以被使用，也可以被有限展开。取决于论证需要。 | 部分沉入背景，部分被展开 | `[因果]` `[对比]` `[证据支持]` `[模式复现]` |
| **结构枢纽** | 一旦说出就成为 sub-topic。后续句子围绕它组织——它不只是一个约束标签，而是一个论证组织者。 | 停留在前景 → 接收 elaboration | `[目的]` `[定义]` |

### 关键区分：结构枢纽 ≠ 句子间关系

结构枢纽型约束（如 `[目的]`）**不替代**结构关系箭头。句 3→句 4 的结构移动仍然是 elaboration（或更具体地说，cause→effect 作为 elaboration 的形式）。`[目的]` 不回答"句 4 对句 3 做了什么"——那是 `elaboration` / `cause→effect` 的工作。`[目的]` 回答的是"句 4 和句 3 在**讨论什么**"。

```
句3 ——— elaborate（用因果链展开）———→ 句4
  ↓                                       ↓
锚定 [目的]                          [因果] 是对 [目的] 的解剖
```

`[目的]` 是 elaboration 的**对象**，不是 elaboration 本身。它是结构箭头所围绕的**主题内核**。

### 为什么这个光谱存在

约束类型的本质决定了它的光谱位置：**结构属性**（权衡、前提、反直觉）暴露后就是事实——事实不接收 elaboration，事实被使用。**意图**（目的）和**指定**（定义）暴露后是开放的——它们天然地邀请"为什么"和"什么意思"的追问，而这些追问的形式就是 elaboration。

### 实例（Ch05 P1）

```
[权衡]（纯概念）：
  句3 暴露交叉补贴 → 完成。句4 不展开权衡本身，而是以它为背景推导目的。

[目的]（结构枢纽，单向）：
  句3 锚定目的 → 句4 围绕它组织。目的只向前看——组织后续句。
```

### 结构枢纽的两种方向

结构枢纽型约束在组织论证时有两种模式：

**单向枢纽**（仅向前看）— 约束被锚定后，只组织后续句的论证方向，不参与前句的追溯关系。例：`[目的]`。

```
句A → 句B: [目的] 被锚定 → 句C: 对 [目的] 的 elaboration
       ↳ [目的] 只向前看
```

**双向枢纽**（同时向后看和向前看）— 约束既作为前句的原因/解释，又作为后续句的组织中心。例：`[定义]` 在特定论证结构中（作者先给出结果，再用定义解释原因）。

```
句A [effect: 结果] ← effect→cause ← 句B [定义] → topic→elaboration → 句C, D
                         ↳ 向后看：回答"为什么"
                         ↳ 向前看：组织"怎么运作"
```

**实例**（Ch05 P3，句 10-11）

```
句10 [effect]: "希望奖学金毫无成功的希望"
  ↓  effect→cause — 句11提供原因
句11 [定义]: "信息不对称 — 学生比管理者更了解自己的未来职业方向"
  ↓  topic→elaboration — 句12-14围绕信息不对称展开
句12-14: 方向性判断 → 退出/加入
```

双向枢纽出现的条件：当作者选择**先宣布结论再解释原因**的论证顺序时，那个同时承载了"原因"和"概念定义"的句子就自动获得了双向性。它不是 `[定义]` 的内在属性（`[定义]` 在 P1 句 2 中就只是单向的），而是 `[定义]` **在特定结构位置**的涌现属性——当一个定义同时是前一句 effect→cause 中的 cause，它就被迫向后看。

#### `[定义]` 的三种变体

`[定义]` 在论证中可以以三种不同形式出现，其枢纽行为取决于**定义在论证弧线中的位置**和**定义内容的展开方式**：

| 变体 | 枢纽方向 | 定义方式 | 实例 | 特征 |
|------|---------|---------|------|------|
| **引入型定义** | 单向（向前） | 单句直接给出，elaboration 本身足够 | P1句2 "收入比例还款" | 新概念首次出现，定义后接收 elaboration |
| **双向枢纽型定义** | 双向（向后+向前） | 单句承载双重功能——既是前句的原因，又是后续句的 topic | P3句11 "信息不对称" | 作者先宣布结论再追溯原因，定义被迫向后看 |
| **回顾型命名** | 分句间拆分（向后/向前分到两个分句） | 分句间 topic→elaboration：前半句回顾性命名，后半句操作性定义 | P4句15 "逆向选择" | 概念已在前面演示过（P3句12-14），这里给出正式名称。前半句（"The result is called..."）向后看，后半句（"sort themselves in or out..."）向前看 |

**回顾型命名的识别信号**：
- 句首有回顾性指针："The result is called..."、"This phenomenon is known as..."、"Economists call this..."
- 概念机制已在前段被完整演示，命名句不引入新内容，只给标签
- 分号结构常见：前半句 = 标签 + 回顾指针，后半句 = 操作性定义
- 段落断点选择：回顾型命名倾向于放在新段首而非前段末——将"收束标签"转化为"重新起跑的出发点"

**回顾型命名的枢纽强度**：回顾型命名可以组织 ≥3 句的 elaboration 块——P4 句15前半句作为 pivot，组织了 {句15后半句（操作性定义）, 句16（因果后果）, 句17（实证）} 三句依赖有序 elaboration（funnel 型：定义→后果→实证）。与 P3句11 的 elaboration（概念内部机制展开）不同，回顾型命名的 elaboration 是**外部后果追溯**——概念的内容已在前段演示，后续句围绕"命名之后会怎样"展开。

#### pivot（结构中枢）

当回顾型命名的 topic 节点同时承担三个结构角色时，称为 **pivot**（结构中枢）：

| 角色 | 方向 | 所属结构 | 说明 |
|------|------|---------|------|
| 长弧终端 | 向后看 | 句11→15 跨段叠加 | 前段论证弧线的收束点——五句论证在此命名 |
| 定义三角顶点 | 双向 | 句13-14 ↔ 句15后半句 | 具体实例→名字→操作性定义，三点语义闭合 |
| 新 block topic | 向前看 | {句15后半句, 句16, 句17} | 组织 funnel 型依赖有序 elaboration |

pivot 不是本段自己产生的——它是前段论证蒸馏出的名字进入新段后自动获得的枢纽地位。段落断点的选择（把命名放在 P4 句首而非 P3 句末）使其从"收束标签"变为"重新起跑的出发点"。

#### 弱结构枢纽（理论概念）

作为对比，当结构枢纽只组织 1-2 句后续句时，称为**弱结构枢纽**（当前 Ch05 P1-P4 中未观测到纯粹实例——P4句15 的 elaboration 块经深潜确认为 3 句 funnel 而非 1-2 句）。保留此概念供未来观测。 |

弱枢纽不意味着论证弱——P4句15 是 Hope 奖学金案例的命名高潮，三段的铺垫（P1共情→P2理论信心→P3机制演示）全为它服务。弱只是指它作为结构枢纽的**组织半径**短，不是论证分量轻。

### 光谱的例外：自组织型约束

`[因果]` 不落在光谱的任何一格。它不是纯概念（因果可以跨句组织论证），不是中间态，也不是结构枢纽——它不是"被围绕的对象"，它是"围绕的方式"。

`[因果]` 和 `[对比]` 是仅有的两个**跨库重叠的类型**：在 `constraint-types.md` 中它们是概念约束（A 是 B 的结果 / A 对比 B），在 `text-structure-types.md` 中它们对应语义角色对 cause→effect 和兄弟关系 contrast。但两者的跨库行为不同——`[因果]` 是自组织的（沿自身方向递归深化），`[对比]` 是并置的（连接但不下钻，见下方对比表）。`[因果]` 的三重身份：

| 身份 | 层面 | 表现 | 例子（P3 句 12→13/14） |
|------|------|------|----------------------|
| 概念约束 | 词句层 | A 导致了 B——连接两个概念 | "方向性判断 → 自利选择" |
| 语义角色对 | 句间层 | 句 A→句 B 是 cause→effect——topic(cause)→elaboration(effect) | 句 12（机制）→ 句 13（高收入端结果） |
| 组织形式 | 论证层 | 因果链是 elaboration 的展开方向——"因为…所以…"不是论证的装饰，是论证的骨架 | 整个句 12-14 沿因果链推进 |

**因果在组织它自己**（P3 句 12→13/14）：

```
句12 [因果: 方向判断 → 自利选择]  ← 概念层面：抽象因果（general）
  ↓  cause→effect                    ← 结构层面：因果在组织自身
句13 [因果: 高收入 → 退出]  句14 [因果: 低收入 → 加入]
        ← 概念层面：具象因果（specific）→
```

一个 general 的因果陈述（句 12），通过结构上的 cause→effect 移动，产出两个 specific 的因果实例（句 13+14）。这不是"结构暴露约束"，这是"结构就是约束，约束就是结构，两者在因果类型中坍缩为一个东西"——general 因果通过 cause→effect 结构展开为 specific 因果，因果在用它自己的方式展开它自己。

**`[因果]` 与 `[对比]` 的对比**：两者是仅有的跨库类型，但跨库后的行为不同。

| | `[因果]` | `[对比]` |
|---|---|---|
| 跨库存在 | 概念约束 + 语义角色对(cause→effect) | 概念约束 + 兄弟关系(contrast) |
| 跨库后的行为 | **自组织**——沿自身方向递归深化 | **并置**——连接两个单元，不产生层级 |
| 结构移动的方向 | 递归下钻：general因果→specific因果，每一层都是因果 | 水平展开：两句平行比较，停留在同一层级 |
| P3 实例 | 句12 [因果] → 句13 [因果], 句14 [因果] | 句13（退出）↔句14（加入）：两句各自是独立的因果实例，contrast 描述它们之间的关系 |
| 一一对应性 | 强——cause→effect 结构几乎总产出新的因果约束 | 强——contrast 结构连接的句子对几乎总能在概念层找到对应的 `[对比]` 约束 |

两者的共性同样值得注意：在少数几个结构关系↔概念约束一一对应的类型中，结构和约束是**同一个关系在不同粒度上的现象**——结构关系是句子之间的"对比/因果/...关系"，概念约束是概念之间的"对比/因果/...关系"。对于这些类型，标注结构关系和标注概念约束是同一件事的两个视角，而非两个独立的工作。

**与 `[目的]` 和 `[定义]` 的区别**：`[目的]` 和 `[定义]` 是结构枢纽——它们被围绕，被展开，但它们不决定展开的方式。作者可以用因果展开目的，也可以用对比展开目的。但 `[因果]` 作为组织形式时，它**同时决定了**被展开的内容和展开的方式——内容就是因果链，方式就是沿因果链推进。它是自己的内容，也是自己的形式。

[目的]（结构枢纽）：
  句3 锚定目的 → 句4 用因果链解剖它。
  目的在两句之间持续存在，且组织着句4的内容。
```

### 阅读和写作时的应用

- **阅读时**：标注到结构枢纽型约束时，立即预期后续句将围绕它组织。标注到纯概念型约束时，不预期后续句对其展开——它会在背景里，作为推理的已知条件。
- **写作时**：如果你想让一个概念在文中持续存在并被深入讨论，选择结构枢纽型的约束来表达它（定义你关心的事，宣布你的目的）；如果你只需要一个过渡性的逻辑连接，使用纯概念型约束（指出一个权衡，标识一个前提）。
