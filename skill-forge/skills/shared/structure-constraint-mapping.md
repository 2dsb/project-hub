# 结构-约束双向映射层

> 连接 [text-structure-types.md](text-structure-types.md)（结构关系——topic→elaboration 为唯一结构关系 + 语义角色对 + 兄弟关系）与 [constraint-types.md](constraint-types.md)（概念约束关系，24 种类型 + 6 种元标注）。本文档是 AI 分析推理的辅助工具——不是权威规则手册，而是基于典型学术论证文本的**经验映射**。不同文体/学科可能有不同映射模式，以原文证据为准。

---

## 一、结构→概念映射（自上而下）

从结构关系类型出发，推断该结构内部通常包含哪些概念约束关系。用于指导 AI 搜索方向：知道该找什么。

**置信度标记**：
- **强 (strong)**：几乎总是出现，缺少时应引起怀疑
- **常 (common)**：频繁出现，但不是必须
- **可 (possible)**：偶尔出现，取决于具体内容

### 语义角色对（旧 Level A）→ 概念约束

> 下表中的"语义角色对"是 topic→elaboration 在不同语义场景下的填充。旧标签保留为速记。

| 语义角色对 | 通常包含的概念约束 | 置信度 | 说明 |
|---------|-------------------|--------|------|
| topic→elaboration | A 详细化 B + A 定义 B | 强 | 主题句→细化句本质上是概念展开，必然涉及详细化和边界界定 |
| claim→evidence | A 详细化 B + A 证据支持 B | 常 | 证据通常是断言的具体化（详细化），且证据为断言提供实证支撑 |
| evidence→analysis | A 是 B 的结果 + A 的价值在于 B | 常 | 分析需要解释证据为何成立（因果）及其意义（价值） |
| general→specific | A 详细化 B + A 以 B 为前提 | 强 | 概括→具体本质是详细化关系，且具例化总以特定条件为前提 |
| specific→general | A 是 B 的结果 + A 的价值在于 B | 常 | 归纳过程中常含因果推理和价值判断 |
| cause→effect | A 是 B 的结果 + A 的程度取决于 B | 强 | 直接因果对应，且结果程度常取决于原因强度 |
| effect→cause | A 是 B 的起源 + A 以 B 为前提 | 强 | 原因追溯常同时揭示隐藏的前提条件 |
| contrast | A 与 B 互斥 + A 对比 B | 强 | 对立关系同时包含逻辑互斥和维度对比 |
| concession | A 与 B 互斥 + A 以 B 为前提 | 常 | 让步承认对立面部分成立（A 以 B 为前提），再反转（互斥） |
| sequence | A 详细化 B + A 是 B 的结果 | 可 | 步骤间有时只是时间顺序，不一定含概念约束 |
| transition | A 的价值在于 B + A 是 B 的结果 | 可 | 过渡句有时只是修辞功能，不新增概念约束 |
| restatement | A 定义 B + A 详细化 B | 强 | 重述本质上是在不同语境下重新界定概念边界，常伴随细微的细化 |

### 段层级 topic→elaboration 语义变体（旧 Level B）→ 概念约束

> 下表中的标签均为 topic→elaboration 在段层级的语义变体。如 `problem→solution` = topic(problem)→elaboration(solution)。旧标签保留为速记。digression 不是结构关系，而是主题偏离标记。

| 语义变体 | 通常包含的概念约束 | 置信度 | 说明 |
|---------|-------------------|--------|------|
| thesis→support | A 详细化 B + A 定义 B + A 以 B 为前提 | 强 | 支撑论据需要展开论点（详细化）、界定概念（定义）、建立逻辑前提 |
| problem→solution | A 解决 B + A 以 B 为前提 + A 是 B 的结果 | 强 | 解决方案以问题诊断为前提（前提），方案旨在解决问题（解决），预期产生结果（因果） |
| question→answer | A 详细化 B + A 定义 B | 常 | 回答通常在展开中界定核心概念 |
| background→foreground | A 以 B 为前提 + A 是 B 的起源 | 常 | 背景铺设逻辑前提和历史起源，为前景论证提供基础 |
| abstract→concrete | A 详细化 B + A 以 B 为前提 | 强 | 理论→应用本质是详细化，且应用总在特定条件下进行 |
| concrete→abstract | A 的价值在于 B + A 是 B 的结果 + A 模式复现 B | 常 | 从案例中提炼规律涉及价值判断、因果归纳和模式识别 |
| claim→counterclaim | A 与 B 互斥 + A 是 B 的反例 + A 对比 B | 强 | 对立立场同时涉及逻辑互斥、反例否证和维度对比 |
| counterclaim→rebuttal | A 是 B 的反例 + A 是 B 的结果 + A 反直觉于 B | 强 | 驳斥需要指出反方逻辑漏洞（反例）并给出正确推理（结果），往往揭示反直觉的真相 |
| chronological | A 是 B 的起源 + A 是 B 的结果 | 常 | 时间序列中的事件通常有因果链条 |
| comparison | A 对比 B + A 权衡 B | 常 | 比较通常揭示维度差异（对比），有时涉及取舍（权衡） |
| synthesis→conclusion | A 的价值在于 B + A 是 B 的结果 + A 精炼 | 强 | 结论需要提炼价值（价值）并总结因果链条（因果），本质是对前文的精炼 |
| digression | A 详细化 B + A 的价值在于 B | 可 | 旁支内容有时只是举例扩展，偶尔揭示隐藏的价值关联，约束稀疏 |

## 二、概念→结构映射（自下而上）

从句/段层面出现的概念约束类型集群，推断段/篇层面可能存在的结构关系。用于 AI 验证发现：底层的约束模式是否符合上层结构预期？

> 当句层面的约束类型组合出现以下模式时 → 怀疑段/篇层面存在对应结构关系（下表中"怀疑的段/篇结构"列为 topic→elaboration 段层级语义变体或语义角色对的简写）：

| # | 句/段层约束模式 | 怀疑的段/篇结构 | 推理逻辑 |
|---|----------------|----------------|---------|
| 1 | A 详细化 B + A 定义 B 在同一主题下跨段高频出现 | thesis→support | 同一主题的反复详细化和界定表明多个段落在支撑一个核心论点 |
| 2 | A 是 B 的反例 + A 与 B 互斥 + A 对比 B 出现在段落边界处 | claim→counterclaim | 段落过渡处的逻辑对立和维度对比暗示立场切换 |
| 3 | A 解决 B + A 以 B 为前提 + A 是 B 的结果 跨段形成链条 | problem→solution | 解决+前提+因果的组合暗示"诊断→方案→预期结果"的论证结构 |
| 4 | A 定义 B 孤立出现在文章起始段 | background→foreground | 开篇对核心概念的界定往往是为后续论证铺设背景 |
| 5 | A 与 B 互斥 + A 对比 B 高频出现在同一段落内相邻句对 | contrast (句间) | 段落内的句级对立和维度对比形成对照结构 |
| 6 | A 是 B 的结果 + A 的价值在于 B + A 模式复现 B 跨段聚合 | concrete→abstract | 因果链+价值判断+模式归纳的组合暗示从现象到规律的归纳过程 |
| 7 | A 是 B 的起源 + A 是 B 的结果 在相邻句中出现 | cause→effect (句间) | 起源+结果的组合表明明确的因果方向 |
| 8 | A 详细化 B 在单段内连续出现 ≥3 次 | topic→elaboration | 持续细化同一主题是主题展开模式的标志 |
| 9 | A 证据支持 B + A 详细化 B 在同一段内出现 | claim→evidence | 证据+细化是"断言→举证"模式的标志组合 |
| 10 | A 策略达成 B + A 解决 B 跨段出现 | problem→solution | 策略+解决的组合暗示有意识的方案设计 |
| 11 | A 反直觉于 B + A 证据支持 B 在相邻句中出现 | counterclaim→rebuttal | 反直觉发现+证据支撑是驳斥的标准模式 |
| 12 | A 权衡 B + A 对比 B 在相邻段出现 | comparison (段间) | 取舍+对比的组合暗示系统性的比较分析 |

## 三、实例级深潜输出格式

当输出概念约束时，将概念约束显式嵌套在其所属的结构边之下，形成"结构框架内嵌概念关系"的层级展示。

### 格式规范

```
P<段落号> → P<段落号> [语义变体]  ← 段间结构边（topic→elaboration 段层级语义变体）
  ├─ '<概念A> <约束类型> <概念B>' (P<段>:句<号>-<号>)  ← 概念约束实例（词句层）
  ├─ '<概念C> <约束类型> <概念D>' (P<段>:句<号>)
  ├─ ...
  │
  ├─ 句<号> → 句<号> [语义角色对]  ← 句间结构边（语义角色对，可选展开）
  │   ├─ '<概念E> <约束类型> <概念F>' (P<段>:句<号>)
  │   └─ '<概念G> <约束类型> <概念H>' (P<段>:句<号>)
  │
  └─ ...
```

### 实例

```
P1 → P2 [thesis→support]
  ├─ '概念A 定义 概念B' (P1:句1-2)
  ├─ '概念B 详细化 概念C' (P2:句3)
  └─ '概念C 以 概念D 为前提' (P2:句5)

P2 → P3 [background→foreground]
  ├─ '<核心概念> 是 <背景概念> 的起源' (P2:句1)
  ├─ '<当前概念> 是 <核心概念> 的结果' (P3:句2-3)
  │
  ├─ 句2 → 句3 [claim→evidence]
  │   ├─ '<论点概念> 定义 <证据概念>' (P3:句2)
  │   └─ '<证据概念> 证据支持 <论点概念>' (P3:句3)
  │
  └─ 句4 → 句5 [concession]
      ├─ '<对立概念> 与 <论点概念> 互斥' (P3:句4)
      └─ '<论点概念> 以 <前提概念> 为前提' (P3:句5)
```

### 格式规则

1. **缩进字符**：使用树形字符 `├─` 和 `└─` 表示嵌套层级，空格缩进对齐
2. **证据可追溯**：每个概念约束标注原文位置（段:句），方便回溯验证
3. **结构边优先**：先展示结构框架（段间→句间），再在框架内展示概念约束
4. **可选展开**：句间结构边默认折叠（仅展示概念约束），当用户选择"深潜"时展开完整的句间结构嵌套
5. **空约束标记**：如果某段间结构边下未发现概念约束 → 标注 `├─ [无约束] 修辞/过渡段落`

### 全要素标注模板

以下模板展示一个完整段落的结构标注应包含的所有维度——块级结构、约束暴露状态、结构光谱位置、多维度句、结构枢纽与嵌套 elaboration。以 Naked Economics Ch05 P1（句 1-5）为实例。

```
句1 [topic: "核心概念"]
  ↓
{句2, 句2, 句3, 句4, 句5} [elaboration: 依赖有序 | 独立]

  [多维度句] 一句承载 ≥2 个并列 elaboration 维度时，拆分标注：
  句2 [约束A]（暴露状态, 光谱位置）: 维度说明
  句2 [约束B]（暴露状态, 光谱位置）: 维度说明
      ↳ 标注共驻关系

  ↓  [结构移动类型]（参数 — 如"取极端值"）

  [暴露型约束] 在结构移动后浮现：
  句3:
    → [约束C]（潜伏→暴露, 纯概念）
        具体内容
        暴露后沉入背景 — 后续句以此为已知条件
    → [约束D]（可陈述→增值, 结构枢纽）
        具体内容 — 锚定
        开始组织后续句 — 后续句围绕它展开

  ↓  结构移动说明：对 [约束D] 进行 elaboration，[约束E] 是展开的形式

  [枢纽展开] 后续句对结构枢纽型约束的 elaboration：
  句4:
    → [约束E] 具体因果链
        ↳ [约束E] 是对 [约束D] 的 elaboration 的**内容**
        ↳ [约束D] 是 elaboration 的**对象**

  ↓  [结构移动类型]

  [终端锚定] 不暴露、不展开、无新约束：
  句5: 具体锚点
    → [无约束] — 功能说明
```

**模板要素清单**（标注时逐项检查）：

| # | 要素 | 对应共享文件 | 何时标注 |
|---|------|------------|---------|
| 1 | 块级主结构（topic → {elaboration}） | text-structure-types.md | 判定段落的组织方式（链式/放射状）后 |
| 2 | 块类型（依赖有序 / 独立） | text-structure-types.md | 删除测试后 |
| 3 | 多维度句 | text-structure-types.md | 一句包含 ≥2 个独立概念操作时 |
| 4 | 句间结构移动（含参数） | text-structure-types.md | 每对相邻句，标注类型 + 特殊条件 |
| 5 | 约束暴露状态（已显式 / 潜伏→暴露 / 可陈述→增值） | structure-constraint-mapping.md | 每个约束被识别时 |
| 6 | 约束光谱位置（纯概念 / 中间态 / 结构枢纽） | constraint-types.md | 每个约束被识别时 |
| 7 | 结构枢纽展开（sub-topic + 嵌套 elaboration） | structure-constraint-mapping.md | 结构枢纽型约束接收后续句展开时 |
| 8 | 终端句功能（锚定 / 暴露隐藏前提 / 平行对比 / 证据+额外 / 闭合性终端） | text-structure-types.md §一.终端功能 | 段落最后一句 — 确定块向更高层级暴露的接口类型 |

**注意**：完整的段落实例（含所有要素的具体值）见 [Ch05 结构分析](../../resources/naked-economics/ch05-structural-analysis.md) P1（依赖有序）和 P2（独立+共生环）。

### 独立 elaboration 模板（含共生环嵌套）

P2 与 P1 共享相同的顶层语法（`topic → {elaboration block}`），但块内组织逻辑完全不同——独立 elaboration + 涌现模式。以 Naked Economics Ch05 P2（句 6-9）为实例。

```
外层 — 块级放射状：
  句6 [topic: "核心主张"]
    ↓
  {句7, 句8, 句9} [elaboration: 独立]

内层 — elaboration 块内部：
  [涌现模式: general↔specific 共生环 — 三句构成自证闭环]

  句7: 操作性的 general（已显式） — how
      将 topic 主张翻译为可计算的操作
      ↓  general→specific
  句8: specific — what it looks like
      极端个例，展示操作落实到人身上的效果
      → [无约束] — 不新增概念关系，功能是让公式可感知
      ↓  specific→general
  句9: 结论性的 general（潜伏→暴露 — 隐藏前提浮现） — why
      归纳回"平均抵消，收支平衡"
      → [前提]（潜伏最深，纯概念）— 对称假设：高低收入者偏离均值的程度恰好对称
          ↳ 暴露后成为 P3 的引爆点

  → [general↔specific 共生环: 句7→句8→句9]
```

**与依赖有序模板的关键区别**：

| 维度 | P1（依赖有序） | P2（独立+共生环） |
|------|--------------|-----------------|
| 块内依赖 | 强——删除中间句打断论证流 | 无——各句独立回应 topic |
| 内部组织来源 | 逐对依赖链（general→specific → cause→effect → claim→evidence） | 涌现模式（共生环——三句互相增强而非接力） |
| 终端句功能 | 锚定——不暴露不展开，将抽象链钉在可感知的数字上 | 暴露——归纳回 general 时暴露了隐藏前提，为下一段的反转埋下伏笔 |
| 在全文中的角色 | 引入案例，建立共情 | 建立理论信心，为下一段制造落差 |
| 有无结构枢纽 | 有——[目的] 组织句4 | 无——没有跨句的 sub-topic |

**判定模板适用**：先做删除测试 → 能独立回应 topic → 使用本模板 → 检查块内是否存在涌现模式（共生环等）。

**注意**：完整的 P2 标注实例见 [Ch05 结构分析](../../resources/naked-economics/ch05-structural-analysis.md) P2。

### 依赖有序 elaboration + 自组织型约束模板（含双向枢纽）

P3 引入了一种 P1 和 P2 都没有的模式：论证从**跨段 contrast**（推翻前段结论）开始，经由**双向枢纽**（定义句同时向后追溯原因、向前组织论证），在 elaboration 块内由**自组织型因果**驱动展开。以 Naked Economics Ch05 P3（句 10-14）为实例。

```
[跨段] P(前)句末 ↔ P(当前)句首 [contrast]
        前段建立的结论（"理论自洽"）vs. 本段的现实（"不成立"）

句10 [effect: 崩坏结果]
      ↳ 先宣告结论，不先解释——"只有一个问题"是锤子，不是推理
  ↓  effect→cause — 先果后因：读者先接受判决，再被告知判决依据
句11 [定义]（已显式, 结构枢纽 — 双向枢纽）
      ↳ 向后看：这是句10的原因（effect→cause 的 cause 端）
      ↳ 向前看：这是句12-14的 sub-topic（topic→elaboration 的 topic 端）
  ↓  topic→elaboration
{句12, {句13, 句14}} [elaboration: 依赖有序]

  句12 [因果]（潜伏→暴露, general, 自组织型）
        ↳ 潜伏→暴露：句11只说"信息不对等"，句12揭示为什么这致命
    ↓  cause→effect（因果自组织：general因果 → specific因果）
  句13 [因果]（specific）  句14 [因果]（specific）
    ↕  contrast — 结构层 contrast = 概念层 [对比] = 同一关系两个粒度
```

**本模板独有的新要素**：

| # | 要素 | 说明 |
|---|------|------|
| 1 | 跨段 contrast | 段落之间的论证转折（不是段内句间）——P2 建立模型 → P3 推翻模型 |
| 2 | effect→cause | 与 cause→effect 方向相反——先宣告结果再追溯原因，论证体验不同 |
| 3 | 双向枢纽 | `[定义]` 同时是 effect→cause 的 cause 端和 topic→elaboration 的 topic 端 |
| 4 | 因果自组织 | general因果→cause→effect→specific因果——因果用自己的方式展开自己 |
| 5 | 并置型跨库 contrast | 句13↔14：结构 contrast 和概念 `[对比]` 是同一关系在不同粒度上的现象 |

**与 P1/P2 模板的对比**：

| 维度 | P1（依赖有序） | P2（独立+共生环） | P3（依赖有序+自组织因果） |
|------|--------------|-----------------|----------------------|
| 论证起点 | 概念锚定（"Hope 奖学金"） | 主张（"能自融资"） | 判决（"不成立"）——跨段 contrast 推翻前段 |
| 首对结构关系 | topic→elaboration | topic→elaboration | effect→cause（先果后因） |
| 枢纽类型 | 单向枢纽（`[目的]`） | 无枢纽 | 双向枢纽（`[定义]`） |
| elaboration 驱动 | 逐对依赖链 | 涌现模式（共生环） | 自组织型因果（因果展开因果） |
| 终端句功能 | 锚定（$75,000） | 暴露隐藏前提 | 平行对比（退出↔加入） |

**注意**：完整的 P3 标注实例见 [Ch05 结构分析](../../resources/naked-economics/ch05-structural-analysis.md) P3。

### 回顾型命名 + 复合叠加模板（含弱结构枢纽）

P4 引入了一种 P1-P3 都没有的模式：句15前半句（"adverse selection"）作为 **pivot**（结构中枢），同时承担三个结构角色——长弧终端（句11→15，向后看）、定义三角顶点（句13-14 ↔ 句15后半句，双向）、新 elaboration block 的 topic（{句15后半句, 句16, 句17}，向前看）。它不是 P4 自己产生的，而是 P1→P2→P3 三段论证蒸馏出的名字。以 Naked Economics Ch05 P4（句 15-17）为实例。

```
                    句15前半句（pivot: "adverse selection"）
                     ╱        │         ╲
长弧收束 ──────────╱          │          ╲────── 新 elaboration block 的 topic
句11→12-14          ╱           │           ╲
topic→elaboration  ╱         定义三角        ╲
+ cause→effect    ╱        /   │   \         ╲
（叠加，跨段）     ╱       /    │    \         ╲
                  ╱      /     │     \         ╲
            句13-14   句15后半句   {句15后半句, 句16, 句17}
          (specific)  (general     [elaboration: 依赖有序]
          退出/加入)   definition)

=== 角色 1 — 长弧终端（向后看）===
句11 [topic: "信息不对称"]
  ↓  topic→elaboration（以因果链为展开形式）
句12→13→14 [elaboration: 依赖有序, 因果自组织]
  ↓  topic→elaboration + cause→effect（叠加, 跨段）
句15前半句 [收束点]: 五句论证弧线在此命名

=== 角色 2 — 定义三角顶点（双向）===
句13-14 → 句15前半句 [specific→general]: 实例→名字
句15前半句 → 句15后半句 [句内 topic→elaboration]: 名字→操作性定义
句15后半句 ⇢ 句13-14 [general→specific（隐含）]: 定义要素→实例对应
三角闭合: 句13-14 与句15后半句语义等价（同一内容，不同抽象层级）

=== 角色 3 — 新 elaboration block 的 topic（向前看）===
句15前半句 [topic: "adverse selection"]
  ↓  topic→elaboration（依赖有序 — funnel 型：定义→后果→实证）
{句15后半句, 句16, 句17} [elaboration: 依赖有序]

  句15后半句 [定义]（已显式）
     操作性定义 — 完成定义三角的同时开启新 block
    ↓  cause→effect（后果追溯）
  句16 [因果链]（已显式, 三层因果）
     自筛选 → 池恶化 → 定价失效 → 模型崩溃
    ↕  P2句9 ↔ P4句16 [contrast（隐含）]: "break even" vs. "cannot recover costs"
    ↓  cause→effect + claim→evidence（叠加, 句间）
  句17 [证据]（已显式）
    → [对比]（潜伏）: 还款不足（逆向选择成本）+ 行政成本（信息验证成本）
       行政成本只参与 claim→evidence，不参与 cause→effect
```

**本模板独有的新要素**：

| # | 要素 | 说明 |
|---|------|------|
| 1 | 回顾型命名 | `[定义]` 的第三种变体——概念已演示，此处只给正式名称。识别信号：句首回顾性指针（"The result is called..."） |
| 2 | 分句间 topic→elaboration | 双向性拆分到两个分句：前半句向后看，后半句向前看 |
| 3 | pivot（结构中枢） | 一个句内节点同时承担三个结构角色——向后收束长弧、双向参与定义三角、向前组织新 elaboration block。pivot 不是本段产生的，是前段论证蒸馏出的名字 |
| 4 | funnel 型依赖有序 | 依赖有序 elaboration 的第二种形态——三个维度（定义→后果→实证）依次下钻，靠逻辑先后排序而非前维度内容提供后维度前提 |
| 5 | cause→effect + claim→evidence 叠加（句间） | 两种结构关系在相邻句对上共存——证据恰好是因果链的终端产物 |
| 6 | topic→elaboration + cause→effect 叠加（跨段） | 叠加可跨尺度出现——句11→句15 长弧叠加与句16→句17 短弧叠加嵌套共存 |
| 7 | 潜伏 [对比] 在证据句内 | 两种信息成本（自筛选成本 + 验证成本）共存但来源不同——一个参与因果链，一个不参与 |
| 8 | 双弧线（长弧+短弧） | 短弧（specific→general）描述收束形式，长弧（叠加）描述收束承载的双重论证目的 |
| 9 | 定义三角 | 名字/一般定义/具体实例三点闭合——语义等价驱动。与共生环不同：三角首尾语义等价，共生环首尾是不同的 general |

**与 P1/P2/P3 模板的对比**：

| 维度 | P1（依赖有序） | P2（独立+共生环） | P3（依赖有序+自组织因果） | P4（回顾型命名+复合叠加） |
|------|--------------|-----------------|----------------------|---------------------|
| 论证起点 | 概念锚定 | 主张 | 判决（跨段contrast推翻前段） | 命名（跨段specific→general） |
| 首对结构关系 | topic→elaboration | topic→elaboration | effect→cause（先果后因） | [句内 topic→elaboration] → 整句 cause→effect |
| 枢纽类型 | 单向枢纽（`[目的]`） | 无枢纽 | 双向枢纽（`[定义]`） | pivot — 回顾型命名，三角色中枢 |
| elaboration 驱动 | 逐对依赖链 | 涌现模式（共生环） | 自组织型因果 | 后果追溯（单句 causal chain） |
| 终端句功能 | 锚定 | 暴露隐藏前提 | 平行对比 | 实证 + 潜伏对比（两种信息成本） |
| 独有结构模式 | 结构枢纽 ≠ 句间关系 | 共生环 + 块级嵌套 | 因果三重身份 + 跨段 contrast | pivot 三角色中枢 + 定义三角 + funnel elaboration + 跨尺度叠加嵌套 |

**注意**：完整的 P4 标注实例见 [Ch05 结构分析](../../resources/naked-economics/ch05-structural-analysis.md) P4。

### 段内自锚定 topic + funnel elaboration 模板（P5）

P5 与 P4 共享 funnel 型 elaboration，但 topic 来源完全不同——P4 的 pivot 是外部蒸馏（P1-P3 论证弧线的终端），P5 的 topic 是句 18 自己锚定的（段内自产）。以 Naked Economics Ch05 P5（句 18-21）为实例。

```
[跨段] P4（一个失败）→ P5（反复模式）[specific→general]

句18 [topic: "会反复出现——太诱人，无法消失"]（段内自锚定）
      ↳ 前半句（"not the last"）: 模式反复 = 断言，需要实例
      ↳ 后半句（嵌入因果）: "too alluring" → 反复复活
          [因果]（已显式）— 断言自带原因，不等后续句证明
          "alluring" = P1-P2 理论美感，"dally" 语调暗含"明知故犯"
      ↳ 不同于 P4句15前半句: 这里是段内自产 topic，不需要外部 pivot 或定义三角
  ↓  topic→elaboration（funnel 型: 实例→分析→裁决）
{句19, 句20, 句21} [elaboration: 依赖有序]

  句19 [证据 + 模式复现]（已显式, 形式-内容重合）
       回应"not the last"——Oregon 2013 具体实例
       ↳ 嵌套括号（Pay It Forward → HOPE → Yale）= 句法表演模式嵌套
    ↓  specific→general（跳升——从具体实例到一般性结构分析）
  句20 [因果×2 + 对比]（已显式）
       回应"too alluring but doomed"——自愿→逆向选择 / 强制→逃离边界
       两个 if-then 并列，各自独立 [因果]，组合成 [对比]——两条路都堵死
    ↓  evidence→analysis + claim→evidence（局部叠加）
  句21 [证据 + 评估（叠加）]
       The Atlantic 的"Radical and Terrible"压缩 P1-P5 全弧线
       Radical = alluring / Terrible = 必然失败
       证据恰好是评估——终端句即全节收束

[跨段闭合] P1→P2→P3→P4→P5: 概念诱惑→理论自洽→机制揭秘→命名崩溃→模式确认
```

**与 P4 funnel 的对比**：

| | P4 funnel | P5 funnel |
|---|---|---|
| topic 来源 | 外部 pivot（P1-P3 蒸馏出的名字） | 段内自锚定（句 18 自己建立） |
| topic 是否需要定义三角 | 是——名字需要实例和定义来填充 | 否——断言自携因果，不需要额外定义 |
| 三个维度 | 定义→后果→实证 | 实例→分析→裁决 |
| 独有模式 | pivot 三角色 + 定义三角 | 嵌入因果 + 形式-内容重合 + 证据-评估叠加 |
| 在全文中的角色 | 命名一个概念 | 确认一个模式——这个概念会反复发作 |

**本模板新要素**：

| # | 要素 | 说明 |
|---|------|------|
| 1 | 段内自锚定 topic | topic 不是前段蒸馏出来的，是句 18 自己生成的——前半句断言 + 后半句嵌入因果，断言自带原因 |
| 2 | 嵌入因果 | 因果不在句间（cause→effect），而在句内（后半句是前半句的原因）——"too alluring"不等句 19 向读者解释为什么 |
| 3 | 形式-内容重合 | 句 19 嵌套括号的句法结构（A→B→C 的括入）表演了概念内容（翻版套翻版）——结构形式就是概念证据 |
| 4 | 证据-评估叠加 | 句 21 的引用同时完成证据（外部权威确认）和评估（"Radical and Terrible" 的价值裁决）——证据恰好是评估 |
| 5 | funnel 型变体: 实例→分析→裁决 | 与 P4 的"定义→后果→实证"维度不同，P5 是"展示实例→解释为什么必然→裁決致命性"的逻辑链 |

### pivot 结构通用模板

当回顾型命名位于段落边界（前段演示机制 → 新段首句命名），且命名句内部分句间存在 topic→elaboration 时，命名句的前半句自然获得 **pivot** 地位——同时向后收束、双向定义、向前组织。这不是 P4 的特例，而是一个可复现的结构模式。

**触发条件**（全部满足时 pivot 模式成立）：

| # | 条件 | 检验方式 |
|---|------|---------|
| 1 | 概念机制已在前段被完整演示（≥2 句的因果链或 elaboration 块） | P(n-1) 是否存在以该概念为核心的论证弧线？ |
| 2 | 命名放在新段首句而非前段末句（段落断点 = pivot 的诞生点） | 命名的段落位置是否在段首？前段末句是否在演示机制而非收束？ |
| 3 | 命名句内分号/冒号分隔为两个分句，前半句 = 回顾性指针 + 标签，后半句 = 操作性定义 | 分句间是否构成 topic→elaboration？ |
| 4 | 命名后的新段内容围绕该名字组织（≥1 句的 elaboration） | 新段后续句是否回应这个名字？ |

**通用标注模板**：

```
                    句X前半句（pivot: "<概念名称>"）
                     ╱        │         ╲
  长弧收束 ────────╱          │          ╲────── 新 elaboration block 的 topic
  P(n-1)论证弧线    ╱           │           ╲
  topic→elaboration ╱       定义三角          ╲
  [+ cause→effect  ╱      /   │   \           ╲
   若因果链是     ╱      /    │    \           ╲
   elaboration    ╱     /     │     \           ╲
   的展开形式]   ╱    /       │      \           ╲
              实例节点    一般定义节点    {定义句, 后果句, 证据句}
           (P(n-1)末尾)  (句X后半句)    [elaboration: funnel 型]

=== 角色 1 — 长弧终端（向后看）===
P(n-1).topic句 [topic]
  ↓  topic→elaboration [叠加类型若适用]
P(n-1).elaboration块
  ↓  [叠加类型]
句X前半句 [收束点]: 论证弧线在此命名

=== 角色 2 — 定义三角顶点（双向）===
P(n-1).实例句 → 句X前半句 [specific→general]
句X前半句 → 句X后半句 [句内 topic→elaboration]
句X后半句 ⇢ P(n-1).实例句 [general→specific（隐含）]
闭合条件: 实例与一般定义语义等价

=== 角色 3 — 新 elaboration block 的 topic（向前看）===
句X前半句 [topic: "<概念名称>"]
  ↓  topic→elaboration（funnel 型: 定义→后果→实证）
{句X后半句, 句Y, 句Z} [elaboration: 依赖有序]
  维度1: 操作性定义
  维度2: 因果后果 [可含跨段 contrast]
  维度3: 实证 [可含叠加]
```

**pivot 的嵌套结构**：

pivot 模板不是独立模板——它是已有模板的**组合器**。一个完整的 pivot 段落内部嵌套了：

| 嵌套层 | 模式 | 位置 |
|--------|------|------|
| 跨段长弧 | topic→elaboration [+ cause→effect 叠加] | P(n-1)→pivot |
| 句内 | 分句间 topic→elaboration | pivot 前半句→后半句 |
| 跨句三角 | 定义三角 | P(n-1)实例 + pivot + 句X后半句 |
| 段内 elaboration | funnel 型依赖有序 | pivot → {句X后半句, 句Y, 句Z} |
| 句间叠加 | cause→effect + claim→evidence | 后果句→证据句 |

五个模式在 pivot 这一个节点上汇合。pivot 本身不是新模式——它是已有模式在特定结构位置（段落边界的回顾型命名）的组合涌现。

**与四种基础模板的关系**：

pivot 不是第五种基础模板——它是 P3（依赖有序+自组织因果）+ P4 的回顾型命名在段落边界处相遇时的**复合结构**。当 P3 型段落的 elaboration 终端恰好落在下一段首句，且该首句同时启动了 P4 型 funnel elaboration 时，pivot 自然产生。四种基础模板（P1 依赖有序 / P2 独立+共生环 / P3 依赖有序+自组织因果 / P4 回顾型命名+funnel）可以组合出 pivot，但 pivot 本身描述的是一种特定的组合方式——段落边界处的"收束+重新起跑"。

**分析时的识别流程**：

1. 检查段边界：前段末句是否在演示机制（而非收束）？新段首句是否有回顾性指针（"The result is called..."）？
2. 检查句内结构：命名句是否有分号分隔？前半句 = 标签，后半句 = 定义？
3. 检查三角闭合：前段的实例和新段后半句的定义是否语义等价？
4. 检查新段组织：命名后的句子是否沿 funnel（定义→后果→实证）推进？
5. 若全部满足 → pivot 模式成立，用本模板标注。

## 四、使用协议

### 分析文本时

**总方法：先建树，再填内部关系**（详见 [text-structure-types.md](text-structure-types.md) "topic→elaboration 的分形结构"）

1. **递归切分**：从最大层级开始（全文 → 段群 → 段 → 句），在每个层级识别 topic 句和它的 elaboration 块边界
2. **构建 topic 树**：将所有 topic 节点按父子关系连接。父 = 被展开者，子 = 展开者
3. **填充核层关系**：在 elaboration 块内部，用 Section 一 的映射表定向搜索概念约束
4. **标注跨块涌现模式**：检查跨块的 contrast、共生环、定义三角等——这些不在树的父子/兄弟关系中自动出现

**旧方法对比**：旧方法将所有句子对视为平等候选项，逐对判断语义角色对。新方法先建 topic→elaboration 树（骨架），再在 elaboration 块内部填充语义角色（血肉），承认 topic→elaboration 是唯一的结构关系——它是文本组织的骨架，语义角色对是 elaboration 块内部的展开方式。

**用 Section 一 指导搜索方向**（核层填充时使用）：
- 在 elaboration 块内部确定了核层结构关系后，参考对应行的"通常包含的概念约束"列表，定向搜索这些约束类型是否确实存在于原文中
- 如果预期约束缺失：可能是分析错误（结构关系判断错了），也可能是文本本身的弱点（结构好但约束稀疏）
- 置信度用于判断异常程度："强"约束缺失 → 高度可疑，应复核结构判断；"可"约束缺失 → 正常

**注意 Section 一的局限**：Section 一 的映射表告诉你"某种结构下通常出现哪些约束"，但它是**共现统计**——它不区分这些约束是在结构移动**之前**就显式存在的，还是被结构移动**暴露出来**的。下面的"约束的暴露条件"补上了这个维度。

#### 约束的暴露条件

不同约束类型在概念被抽象定义时处于不同的状态。有三类，不是两类。

**状态一：已显式** — 定义为的就是直接说出来。不需要结构移动来暴露，elaboration 本身足够。

**状态二：潜伏→暴露** — 概念本身携带该属性，但在抽象层面不可见。需要特定的结构移动将其从潜伏状态拉到显式状态。不是"作者忘了说"，而是"这个抽象层级本身就看不到它"。

**状态三：可陈述→增值** — 可以在任何抽象层级被说出来，但每次结构移动都在给它**增加分量**，而不是在"发现"它。同样一句话，在 general 层面说出来是空话，经过了 specific→general 的闭环之后再说就是被检验过的结论。这类约束有一个额外特征：**结构枢纽性**——它一旦被说出，就不再只是一个约束标签，而是变成后续论证可以围绕它组织的 sub-topic。

| 约束类型 | 状态 | 需要的结构移动 | 能否成为 sub-topic | 为什么 |
|---------|------|--------------|-------------------|--------|
| `[定义]` | 已显式 | 不需要额外移动，elaboration 本身足够 | 能——定义之后可以举例、对比、展开。**三种变体**：引入型（单向枢纽）、双向枢纽型、回顾型命名（分句间 topic→elaboration，弱枢纽）。详见 [constraint-types.md](constraint-types.md) 第四节。 | 定义是"指定"，指定完之后自然成为可被操作的对象。变体的枢纽行为取决于定义在论证弧线中的位置和段落断点的选择。 |
| `[对比]` | 半显式 | elaboration + 否定性边界建立 | 有限——对比确立后通常不接收进一步展开 | 边界画定之后论证继续推进，不围绕边界本身组织 |
| `[权衡]` | **潜伏→暴露** | general→specific（取极端值） | **不能**——暴露后是事实，被使用而非被展开 | 抽象公式不携带极端值信息。暴露后它作为已知条件进入后续推理 |
| `[因果]` | **潜伏→暴露** | cause→effect 或 effect→cause | 有限——因果链被建立后通常流向下一步推论 | 因果链的方向在被结构展开之前是模糊的 |
| `[前提]` | **潜伏→暴露**（最深） | contrast 或 counterclaim→rebuttal——系统被挑战时才暴露 | 不能——暴露时往往意味着论证方向即将反转 | 前提在模型正常运行时不浮现，直到模型崩溃你才知道它依赖了什么 |
| `[目的]` | **可陈述→增值** + **结构枢纽** | 可在任何层级被说出；一旦说出，后续结构移动围绕它组织 | **能——且以此为特征**。目的锚定后，后续句可以用因果解剖它、用证据支持它、用反例质疑它 | 目的是人的**设计意图**，不是机制的**结构属性**。但它和定义有一个共同点：一旦锚定，就可以被反复展开——只是定义被展开的方向是几何的（画边界），目的被展开的方向是因果的（追链条） |

#### `[目的]` 的双重身份

`[目的]` 是唯一一个同时占据两种角色的约束类型：

- **在 constraint-types 表中**：它是一个概念约束——A 的目的是 B
- **在结构分析中**：它是一个 **sub-topic**——一旦说出，可以接收 elaboration

这不同于其他约束。`[权衡]` 被暴露后只做一件事——作为已知条件被后续推理使用。你不会对 `[权衡]` 本身进行 elaboration——你不会说"这个权衡具体意味着 A 比 B 多付 30%……"那不是对权衡的展开，是对数字的补充。但你会对 `[目的]` 进行 elaboration——"这个目的具体意味着什么？"→ 句 4 用因果链回答。

**实例**（Ch05 P1，句 2→句 3→句 4）

```
句2 [定义] 公式：还款额 = 年收入 × 百分比 × 年限
  ↓  general→specific [结构移动]
句3: 投行家（天花板）vs. 社工（地板）

结构移动的产出：
  → [权衡] 高收入者多还 = 低收入者少还 —— 潜伏→暴露。完成。
  → [目的] "which was exactly the point" —— 锚定。开始。

句4 不是和句3并列的另一条"目的陈述"——
  句3 锚定了 [目的]，句4 是对 [目的] 的 elaboration：
    [目的] → {[因果] 作为 elaboration 的内容}
      大额债务 → 被迫"做好"而非"行善"
        → 无法选择低薪但有益社会的工作

  句4 的 [因果] 不是在句4里独立产生的新约束——它隶属于对 [目的] 的展开。
  换句话说：因果关系是 elaboration 的**内容**，[目的] 是 elaboration 的**对象**。
```

`[权衡]` 在 general→specific 中被暴露后，论证继续往前——它不会衍生出自己的 elaboration 子块。`[目的]` 在句 3 被锚定后，句 4 围绕着它组织了一整句的因果展开。这就是"结构枢纽性"：目的不是一扇被打开后就关上的门，而是一扇被推开后里面还有走廊的门。

#### 结构枢纽的两种方向

`[目的]` 是**单向枢纽**——只向前看，组织后续句。但 `[定义]` 在特定结构位置上可以成为**双向枢纽**——同时向后追溯前句的原因，向前组织后续论证。

**对比**：

| | 单向枢纽（`[目的]`，P1） | 双向枢纽（`[定义]`，P3） |
|---|---|---|
| 向前看 | 句3锚定目的 → 句4围绕它展开因果链 | 句11定义信息不对称 → 句12-14围绕它展开机制 |
| 向后看 | 无——句2→句3是 general→specific，句3的目的不是句2的原因 | 句10→句11是 effect→cause — 句11的定义**就是**句10判决的原因 |
| 为何方向不同 | 目的在 argue 中的位置是"意图声明"——它解释"为什么设计"，不解释"为什么失败" | 当作者先说结论再说原因，承载原因的定义句就被迫获得双向性 |

**实例**（Ch05 P3，句 10-11）：

```
句10 [effect: 计划失败 — 宣判]
  ↓  effect→cause — 追溯"为什么"
句11 [定义: 信息不对称] — 双向枢纽
      ↳ 向后：这是计划失败的原因
      ↳ 向前：这是后续论证要展开的概念
  ↓  topic→elaboration
句12-14: 方向性判断 → 退出/加入
```

**判定**：枢纽的方向性不是约束类型的内在属性，而是**约束在论证结构中所处位置的涌现属性**。当 `[定义]` 同时是前一句 effect→cause 关系中的 cause 端，它就是双向的。当 `[定义]` 只是 topic→elaboration 关系中的 topic 端（如 P1 句 2），它就是单向的。`[目的]` 目前只在单向枢纽的场景中被观测到——它总是出现在"作者声明意图然后展开"的结构中，不出现在"先给结果再追溯原因"的结构中。

#### `[因果]` 的三重身份

`[因果]` 和 `[对比]` 是仅有的两个同时跨越概念约束库和句间结构库的类型。两者以不同方式使用这种跨库存在——`[因果]` 是自组织的（沿自身方向递归深化），`[对比]` 是并置的（水平连接，不产生层级）。`[因果]` 以三种身份运作：

| 身份 | 层面 | 回答的问题 | P3 实例 |
|------|------|----------|---------|
| 概念约束 | 词句层 | "什么导致了什么？" | "方向判断 → 自利选择"（句 12） |
| 句间结构 | 句间层 | "这句对前一句做了什么？" | 句 12→句 13 [cause→effect] |
| 组织形式 | 论证层 | "论证沿什么方向推进？" | 句 12-14 整个 elaboration 沿因果链展开 |

**因果在组织它自己**：

```
句12 [因果: 方向判断 → 自利选择]  ← 概念：abstract cause（general）
  ↓  cause→effect                    ← 结构：因果在组织自身
句13 [因果: 高收入 → 退出]  句14 [因果: 低收入 → 加入]
        ← 概念：specific causes →
```

一个 general 因果陈述通过结构上的 cause→effect 移动产出两个 specific 因果实例。这不是"结构暴露了约束"，这是 **约束就是结构，结构就是约束**——因果用它自己的方式展开它自己。general 因果 → specific 因果，每一层都是因果。

**与 `[对比]` 的区别**：`[对比]` 同样跨库存在于概念约束和句间结构两个类型库中，但它是**并置型**而非**自组织型**——contrast 结构连接两个句子，让它们平行比较，但不产生层级或递归深化。当被连接的句子各自承载对立的概念内容时（如 P3 句13"退出" vs 句14"加入"），结构层面的 contrast 和概念层面的 `[对比]` 是同一个关系在不同粒度上的现象——不是两个独立的工作。

**阅读时的特殊处理**：遇到 `[因果]` 约束时，不能像对待其他约束那样"标注完就结束"。因果既是约束又是结构——标注它也是标注它连接的下一个句子可能的方向。这个特殊性在其他 23 种约束中不存在。

#### 阅读优先序：结构先行，约束Search在后

暴露条件的存在意味着标准的阅读程序应该是：

1. **先判定句间结构**：这段句子之间是什么结构关系？general→specific？cause→effect？elaboration？
2. **根据结构确定搜索区间**：如果判定为 general→specific，去 **specific 端**搜 `[权衡]` `[对比]` 等潜伏型约束
3. **根据结构预期读约束**：如果结构是 elaboration，预期 `[定义]` 在源端（topic 展开处）；如果结构是 cause→effect，预期 `[因果]` 在结构边沿线

反过来做（先满天搜约束，再用约束拼结构）容易犯的错误：在句 2 里找 `[权衡]`——句 2 的公式看起来似乎暗含权衡，但实际不在那里，因为权衡不在公式表面，在公式被推向极端值之后的反弹里。你不先识别结构移动，就不知道去哪句找什么。

这与 Section 一的映射表配合使用：映射表告诉你"你应找什么"，暴露条件表告诉你"去哪里找、为什么它在那儿"。

### 用 Section 二 验证发现
- 当已识别出底层概念约束后，反向检查：这些约束的组合模式是否暗示某种高层结构关系？
- 如果 Section 一 推断的结构关系与 Section 二 推断的不一致 → 优先采信 Section 二（自下而上的证据更可靠）
- Section 二 的映射是启发式的——它提示可能性，不给出确定性结论

### 输出结果时

**用 Section 三 的格式展示实例级深潜**：
- 默认输出层：段间结构边 + 概念约束（句间结构边折叠）
- 用户说"展开这段"或选择"深潜"时：展开该段的句间结构边
- 概念约束始终标注原文位置

### 重要原则

1. **本文档是推理辅助工具，不是权威规则** — 结构关系判断以原文证据为准，不以映射模式为准
2. **不同文体可能有不同映射** — 学术论文、新闻评论、叙事散文的映射模式不同。本文档基于典型学术论证文本，其他文体仅供参考
3. **映射会随着数据积累而更新** — 如果反复出现某映射与原文不符的情况，更新对应行的置信度或约束类型列表
4. **缺失 ≠ 错误** — 某结构关系下缺少"强"置信度的概念约束，可能是文本本身的特征（如纯修辞段落），不一定是分析错误

### 自封闭 topic + 嵌套对 + 闭合终端模板

P5 引入了一种与 P1-P4 都不同的模式：topic 句本身内置了因果答案（自封闭 topic），elaboration 被提升为验证+深化+裁决。块组织不是 funnel（三维独立）而是 {{句19, 句20}, 句21} 的两层嵌套——句19→句20 构成 specific→general 嵌套对（指代依赖，非内容依赖），句21 单独作为闭合性终端。以 Naked Economics Ch05 P5（句 18-21）为实例。

```
                          句18（自封闭 topic）
                     ╱              ╲
           前半句（主张）          后半句（内置因果）
        "not the last"        "too alluring to go away"
        [模式复现: 需要验证]     [因果: topic内部闭合]
                 ╲              ╱
                  ╲            ╱
                   ╲          ╱
                    ╲        ╱
                {{句19, 句20}, 句21}
          [elaboration: 嵌套对 + 闭合终端]
           specific→general 对      裁决

跨段: P4→P5 [specific→general]
  P4（一个案例: Yale）→ P5（反复模式: 必然且无解）

=== 句18: 自封闭 topic（text-structure-types.md §一.角色变异）===
  topic 句内部完成因果闭合——"too alluring to go away" 嵌入 topic
  → elaboration 不回答"为什么反复"，而是: 验证 + 深化 + 裁决

=== 块1: {句19→句20} [specific→general 嵌套对] ===
  句19 [证据 + 模式复现]（已显式）
    → Oregon 2013 实例，嵌套定语从句 = 空间换时间的修辞压缩
    ↓  specific→general（指代依赖，非内容依赖）
  句20 [因果×2 + 对比]（已显式）
    → 两难 (dilemma): contrast 特殊变体——"A 失败且 B 失败"
    → 路径1（自愿→逆向选择）= P3 全段回声
    → 路径2（强制→逃离边界）= P5 自产新论证

=== 块2: 句21 [闭合性终端]（text-structure-types.md §一.角色变异）===
  证据-评估叠加: The Atlantic 引用 = evidence + evaluation 不可分离
  "Radical"=P1-P2, "Terrible"=P3-P5

=== 五段弧线闭合 ===

```
