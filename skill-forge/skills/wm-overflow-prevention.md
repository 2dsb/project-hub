# 工作记忆溢出预防

**触发条件**：
- 用户描述感受到"脑中线程太多""切换不过来""记不住整个流程"时主动触发
- AI 观察到用户同时进行 ≥3 个并行的信息搜集/决策任务时，**先询问而非直接执行**："我注意到你同时在处理 N 件事，需要触发工作记忆溢出预防吗？"用户确认后再进入 Step 0

**核心原则**：大脑做处理，外部做存储。工作记忆容量 ≈ 4±1 个组块，超出即崩溃。解法不是更努力，是把该外化的东西写下来。

## 离线

**用户职责**：

1. **察觉溢出信号**：当你感觉"脑中线程太多""记不住依赖关系""来回切换窗口很疲惫"时，主动说"触发工作记忆溢出预防"或直接描述症状。
2. **准备外化工具**：手边常备纸笔或随时可打开的空白文档——外化依赖纸或屏幕，不依赖记忆。
3. **信任外化**：写下来之后，强制自己不再在脑中维护已写下的信息。看一眼纸/文档就能想起来的东西，不值得占用脑内槽位。
4. **用 AI 替代多网页搜索**：配置型、操作步骤型任务，优先问 AI 分步指引，而非打开 10+ 个网页自己拼凑。

## 在线

**AI 行为**：

### Step 0: 症状分流（若症状模糊则先执行此步）

若用户只说"好累""脑子乱"等模糊描述，未明确指向模式 A 或 B，先问两个问题判別：
1. "现在脑中在同时追踪几件事？" → 若 ≥5 → 倾向模式 A
2. "其中有没有'要先……才能……'的依赖链？" → 若 ≥3 层 → 同时有模式 B

判断清楚后进入 Step 1。若用户已明确描述症状（如"开了太多网页"或"前提步骤太多记不住"），跳过此步直接进入 Step 1。

### Step 1: 识别模式

根据用户描述，判断属于哪种模式：

| 模式 | 信号 | 判断依据 |
|------|------|---------|
| A（横向搜索过载） | "打开了很多网页""切换不过来""多线程" | 同时维护 ≥5 个待消化的参考源 |
| B（纵向依赖嵌套） | "要先……才能……""前提步骤""整条链记不住" | 脑中嵌套 ≥3 层依赖关系 |

两种模式可能同时出现。若同时出现 → 先处理 B（纵向），再处理 A（横向）。理由：B 决定做什么，A 决定怎么做，顺序不能反。

**若用户纠正**："不是这个问题" → 直接询问"是信息太多（模式 A）还是依赖太深（模式 B）？"让用户在 A/B 之间选择，然后进入对应处理步骤。

### Step 2.A: 应对搜索过载

1. **紧急停损**：要求用户关掉所有参考网页（或全部加入书签后关闭）。若用户拒绝关闭 → 退而求其次：将页面分为两组——"当前步骤直接需要"vs"后续可能需要"，只保留第一组（≤3 个），其余加书签后关闭。
2. **写 3 步链**：让用户用一句话写出要完成的事，拆成 3 步以内的执行链。如果 3 步装不下 → 说明还没想清楚，退回重新定义目标。
3. **选择 1 个最佳参考源**：从保留的页面中，只保留官方文档或 1 篇最直接相关的博客。其余不碰。
4. **撞墙才搜**：执行第 1 步。卡住了再搜。不预判后续步骤需要什么。

### Step 2.B: 应对依赖嵌套

1. **外化依赖树**：让用户从最终目标反推，把所有前提条件写成树形结构。用缩进或 bullet list 即可，不需要任何格式规范。关键是写下来，不是写好看。
2. **标注叶子节点**：逐节点检查——该节点是否有子依赖？若没有 → 标记为"可立即执行的叶子"。只标叶子，不标非叶子。
3. **自底向上执行**：从叶子开始。每完成一个节点就划掉。用户只需关注"下一个可执行的叶子是什么"，不需要记住整棵树。
4. **动态追加**：执行中若发现新依赖 → 直接在树上加子节点 → 回到第 2 步（重新标注叶子）。

### Step 3: 确认切换完成

执行完成后，询问用户确认以下状态：
- "现在脑中在追踪几件事？" → 若回答 ≤2（当前步骤 + 下一步）→ 通过
- 所有待执行项已外化到纸上/文档中，用户不再靠记忆维护

**后续复发处理**：若同一会话中用户再次出现溢出信号 → 回到 Step 1 快速确认模式（跳过 Step 0）。若模式与上次相同且外化的步骤链/依赖树还在 → 直接从对应模式的执行步骤开始（跳过外化阶段），检查用户是否偏离了已写下的计划。
