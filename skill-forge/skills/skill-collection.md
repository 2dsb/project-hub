# Skill 收集方法

**元技能**：识别和固化个人技能的标准化流程。适用于任何领域——从日常工作中发现可复用的做事方法，将其形式化为 Skill 实体。

## 离线

**我的职责**（不在对话中时）：

做完一件事或遇到一个特定情境后，先问自己一句：**"这件事/这个情境是否会出现不止一次？"**

- 否 → 无需处理
- 是 → 继续关注两类信号：
  - **惊讶信号**："咦，这次比之前快/顺/对得多？" → 方法可能值得固化
  - **挫败信号**："又在这里卡住了" → 失败模式值得记录

触发后用一句话记下三个要素：**情境 + 做了什么 + 效果**。例如：
- "刷解析几何卷子时，先花 5 分钟通读全卷标难度再开始做，最后多出 15 分钟检查，正确率明显提高"
- "背 Anki 实词时先看例句再背释义，比直接背快很多"

记在哪都行（手机备忘录、草稿纸、脑子）。下次对话时说"我有一个 skill 想固化"，进入在线流程的 step 2。

不需要每件事都问自己。只对两类信号敏感。每天自然不超过 1-2 条。

## 在线

### 触发时机

AI 在以下任一情况时启动本 skill：

- 完成一个任务后（M19 自动触发："效果评价？"）
- 遇到失败后反思出原因和改进方式
- 观察到他人的有效方法并自己复现成功
- 注意到某个做事模式在 ≥2 个不同场景中有效
- 用户主动说"这个可以固化为 skill"

## Steps

- order: 1
  action: "识别可固化经验：回顾刚完成的任务或反思内容，判断是否满足以下条件——(1) 有明确的触发场景，(2) 做事的步骤可被描述和复现，(3) 效果可被评价（好/差）。若满足 → 继续下一步；若不满足 → 告知用户'这个暂不适合固化为 skill，原因：...'"
  note: "不是所有经验都适合固化为 skill。一次性情境、纯运气因素、或步骤过于模糊的，先作为 idea 记录。"
  execute_skill: null
  skill_args: {}
  on_failure: "stop"

- order: 2
  action: "捕捉原始经验：请用户用自然语言描述——'在什么情境下，你做了什么，结果如何？'将描述写入对话上下文，不要求结构化。"
  note: "这一步的关键是快速捕捉，不要让结构化要求打断用户的表达。"
  execute_skill: null
  skill_args: {}
  on_failure: "stop"

- order: 3
  action: "提炼步骤序列：从用户的描述中提取可复用的操作步骤（3-7 步为宜），每个步骤包含——做什么 + 关键判断点/注意事项。向用户展示提炼结果，确认是否准确。"
  note: "提炼原则：(1) 每步一个清晰动作，(2) 保留决策分支点，(3) 去除一次性情境细节。确认后追问：'这个方法的整体效果——好 / 一般 / 差？'"
  execute_skill: null
  skill_args: {}
  on_failure: "prompt"

- order: 4
  action: "固化 Skill 文件：根据评价设定 score——好=+1.0，一般=0.0，差=-1.0（并追加 defects 条目）。生成 skills/<slug>.md（含完整 frontmatter + 步骤序列），告知用户。"
  note: "文件名规则：slug 使用英文短横线，3 个词以内概括核心动作。"
  execute_skill: null
  skill_args: {}
  on_failure: "stop"

## 补充规则

- 若经验来源于失败（用户说"效果差"），score 设为负值，并追加 defects 条目记录失败原因
- 若步骤在 2 个以下，考虑是否为"习惯"而非"技能"——习惯记录在 reminders.md，技能记录在 skills/
- 若与已有 skill 高度重叠，优先更新已有 skill 而非创建新的
- 每个 skill 文件创建后，自动通知用户，并在 INDEX 日期刷新
