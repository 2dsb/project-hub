# 执行追踪

**计划的价值不在于被遵守，而在于让你知道自己正在偏离**。执行追踪就是偏差检测 + 根因判断 + 调整决策。

## 离线

**用户职责**：在 AI 对话外按计划执行时，做好以下记录，以便回到对话时 AI 能准确判断状态——

1. **进度标记**：每完成一步，在计划表中勾掉该步骤。若完成时间远超预估（建议值：1.5 倍，经验值，可按实际情况调整），在对应步骤旁标注"超时（实际 X min）"。
2. **偏差记录**：实际产出和预期是否一致？不一致的话，差在哪里？——一句话记在对应步骤旁（例如："输出比预期少了用户分群分析""数据库连接失败，用了 CSV 替代"）。
3. **问题标记**：以上两种情况（超时 / 产出偏差）出现时，在该步骤旁标注"⚠"。若同一步骤连续发生（建议值：2 次，经验值，可按实际情况调整），标注"⚠⚠"并暂停执行，不要继续推进。

**回到对话时**：告诉 AI"继续执行"或"我完成了步骤 X"，附上你的偏差记录和⚠标记。AI 会接管诊断和调整决策。

**关键原则**：
- 最大的陷阱不是执行出错，而是**需求已经变了、你还在按原计划死磕**
- 超时和偏差不是失败，是信号——回到对话时主动提及，AI 会帮你判断是执行问题还是需求问题
- 你只需要记录"发生了什么"（事实），把"为什么发生、该怎么办"（判断）留给 AI 在线阶段

## 补充规则

### 与上下游 skill 的关系
- 本 skill 是 general-task-flow 阶段 4 的详细展开
- 与 skill-collection 的联动：执行中发现的特殊经验/教训 → 收尾时触发 skill-collection

### 异常情况处理
- 用户说"先跳过这一步" → 允许，但在计划表中标注"跳过"，后续检查点确认是否需回头补
- 用户明确表示"不做了""放弃这个计划""取消"→ 确认意图后：(1) 在计划表中标注"已放弃"及放弃原因，(2) 更新对应项目的 progress 状态，(3) 若用户愿意，记录放弃原因作为经验触发 skill-collection
- 若计划中 3 步及以上均出现偏差且调整无效 → 不是单步执行问题，是计划本身不可行。建议终止计划，回到 needs-clarity 以更小范围重新制定

### 回溯规则
- 计划表中步骤全部完成但用户不满意结果 → 不是执行问题，是需求问题，回到 needs-clarity
