# Memorization in the Learning Pipeline

## Core Question

Where does memorization — deliberate, systematic retention of learned material — fit into the learning pipeline?

## Current Intuition

Memorization probably belongs at **Sink**, as a retention-oriented output mode distinct from the three expression-oriented ones (analogy, translation, reconnection doc). But only a hunch — not tested.

## Potential Position: Sink (4th Mode)

The current Sink has three output modes, all about *expression*:

| Mode | Audience | Function |
|------|----------|----------|
| Analogy | Others | Lower cognitive barrier, test understanding |
| Translation (CN→EN) | Self (practice) | Expose fuzzy spots, expression skill |
| Reconnection Doc | Future self | Compress and reconstruct understanding |
| **Memorization** (candidate) | **Future self** | **Retain facts/relationships against decay** |

The distinction: reconnection docs are for *structural reconstruction* — you read the doc to rebuild a mental model. Memorization is for *element-level retention* — individual facts, formulas, vocabulary that need to survive time gaps without the overhead of full reconstruction.

## Why Not Integrate Yet

The learning pipeline has been validated through real-world runs (MIT 6.S184, DL Book Ch2/Ch3). Adding an untested component would pollute a structure that's earned its confidence. Per `structural-patience`: this is one intuition with zero practice instances. Wait.

## Open Questions

- Is memorization a Sink mode, or a parallel retention axis running alongside the whole pipeline?
- Does memorization interact with the Router stages? (e.g., "this concept is high-leverage enough to memorize" vs "this is lookup-only")
- What form would memorization output take? Spaced-repetition cards? Summary tables? Something else?
- Does the reconnection doc already serve part of the memorization function? (It encodes relationships — does that reduce the need for explicit memorization of facts?)
