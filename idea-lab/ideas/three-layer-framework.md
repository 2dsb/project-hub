# Three-Layer Framework as Starting Lens for Reconnection Docs

**Insight**: When building a reconnection doc for a new chapter, the three-layer framework (观念层 conceptual / 技术架构层 technical architecture / 纯数学层 mathematical) can serve as the *starting lens* for examining every concept — rather than being derived bottom-up from content analysis.

**Why this matters**: During the Ch5 reconnection model work, we spent significant effort sorting each of 116 concepts into the right layer. The three layers emerged organically from the content. But if we *start* with the three-layer scaffold and ask of each concept "which layer? how does it connect to the others?", the process becomes much more efficient.

**The three layers**:
1. **Conceptual layer (观念层)** — ideas, philosophies, observations about reality that induce technical architecture. Examples: NFL theorem, Occam's razor, curse of dimensionality observation
2. **Technical architecture layer (技术架构层)** — the (Q, A) structure: what the algorithm *is*, its execution flow, components, constraints. The core operation is 限定 (constraining from high-entropy natural language to low-entropy math)
3. **Mathematical layer (纯数学层)** — precise mathematical objects, equations, properties. Connected to conceptual layer via natural-language concepts as bridges; embedded into technical architecture at specific insertion points

**Key dynamic**: The three layers are bidirectionally related — conceptual induces technical, mathematical supports conceptual, technical embeds mathematical. A concept often spans two layers with different meanings at each.

**Application**: Next chapter's reconnection doc should begin by asking of each concept: "Is this conceptual, technical, or mathematical? Which layer does it primarily live in? What does it link to in the other layers?" The answer pattern should drive structure, not the other way around.
