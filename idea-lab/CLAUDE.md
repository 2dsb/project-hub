# idea-lab — Knowledge Layer

Two input sources → one melting pot:

```
Literature Notes ──→ ideas (melting pot) ←── Project Notes
                      │
                      └── connections emerge, insights compound
```

## Structure

- **ideas/**: The melting pot — all ideas live here. Knowledge from literature notes and project notes feeds in; connections emerge and insights compound.
- **literature-notes/**: Content from books/web, rewritten in own words. Source: 卡片笔记写作法. Do NOT auto-translate — Chinese is source of truth.
- **project-notes/**: Learning extracted from completed projects.

## Idea Metadata

7 fields: `id`, `title`, `tags`, `summary` (LLM-generated, ≤100 words), `importance` (0-10 PageRank, or -1 manual pin), `connections` (links to other ideas), `body_hash` (auto-managed, for change detection).

### Importance Convention

Only two states:

| Value | Meaning | Overwritten by maintain? |
|-------|---------|--------------------------|
| `-1` | Manually tagged "very important" | Never |
| Anything else | PageRank auto-score | Every run |

Set an idea to `importance: -1` to pin it; all others are auto-managed.

**CRITICAL — When creating or editing ideas:** Claude must NOT manually write `summary`, `connections`, `importance`, or `body_hash`. These are generated by `maintain.py`. Claude fills only: `id`, `title`, `tags`, and body text. The only exception: set `importance: -1` to manually flag an idea as "very important" (PageRank will never overwrite it). Run `python maintain.py` after to auto-generate the rest.

## Connection Types

Connections between ideas come from two sources:

1. **Auto-generated** — `compute_connections.py` uses embedding similarity to discover semantic links. Written to .md files by `write_connections.py`. High-confidence (≥0.60) connections are written directly; lower-confidence ones are tagged `# review: 0.xxx` for later audit.
2. **Manual** — You notice a non-obvious relationship (causal chain, practical complement, etc.) that semantic similarity misses. Add it directly to the frontmatter `connections:` block.

Both coexist in the same `connections:` list. **Manual > auto** — the scripts never overwrite or duplicate existing connections. Auto-generated connections are marked `# auto`; low-confidence ones additionally show `# auto, review: 0.xxx`. Unmarked connections are manual. Run `python rebuild_index.py` after manual edits to refresh the index.

- **ideas-index.json**: Auto-generated from all idea files. Run `python rebuild_index.py` to regenerate.
- **connection-suggestions.json**: Generated by `compute_connections.py`. Suggested semantic links between ideas (embedding similarity + gap detection). Reviewed suggestions are written back to .md files by `write_connections.py`.
- **graph.html**: Interactive relationship graph. Nodes colored by Louvain community, sized by connection count. Toggle between core (≥2 connections) and full view. Open in browser or run `python generate_graph.py` to regenerate.

## Maintenance

After adding or editing ideas, run maintenance scripts from the repo root:

```
python maintain.py                  # full pipeline: summaries → connections → write → importance → index → graph
python maintain.py --skip-summaries # skip LLM API calls (tags-only changes, manual conn edits)
```

Individual scripts when only one step is needed:

| Script | What it does | When to run alone |
|--------|-------------|-------------------|
| `generate_summaries.py` | Call DeepSeek to generate `summary:` field | After editing idea body text |
| `compute_connections.py` | Embedding similarity → gap detection → suggestions | After changing tags or summary |
| `write_connections.py` | Write suggestions back to .md files (dedup) | After reviewing suggestions |
| `compute_importance.py` | PageRank importance scoring (0-10) | After adding/removing connections |
| `rebuild_index.py` | Regenerate ideas-index.json | After manual connection edits |
| `generate_graph.py` | Generate interactive graph.html | After any connection or tag changes |
